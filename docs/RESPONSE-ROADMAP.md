# 响应速度与后续工作

基线：0.4.4。设备命令已经在后台执行，同一设备的设置串行写入；单次修改只刷新目标设备。保留这些行为，避免为了速度跳过读回确认或并发改写同一设备。

## 本轮优先项

首页和详情页绘制路径不应反复打开、解析插件安装记录。把仅供显示的安装状态和设备图片一起加载，在驱动管理页关闭时重载。实际写入仍由插件管理器重新验证安装记录与 DLL，不使用显示缓存作为操作许可。

验收：绘制函数不访问插件记录文件；安装、卸载后显示状态重新加载；新型号的进程注册表仍需重启才能载入。不把减少文件访问次数当成已测量的帧率或延迟提升。

## 0.4.4 已实现

全量界面刷新采用最多四个后台读取工作线程，按完成顺序回传单台设备状态。候选 VID/PID 集合相交的型号合并为串行组，避免共享接收器同时通信；单设备设置与 CLI 仍走原串行流程。缺少 Windows 父设备身份的不同 VID/PID 组合不能保证被识别为同一物理设备。软件模拟覆盖快设备先显示、慢设备完成及旧状态保留，不把模拟时序当作真实硬件提速百分比。

## 后续队列（尚未完成）

| 顺序 | 工作 | 完成条件 |
| --- | --- | --- |
| 1 | 为启动、页面切换、手动刷新、单次写入分别记录阶段耗时 | 只记设备插件编号、操作类型和耗时，不记录序列号、文件路径或宏内容；可由用户主动导出 |
| 3 | 插件安装后动态更新设备列表 | 按设备 key 保留配置与选择；先停止该设备操作再切换版本；卸载中的设备不能继续写入；保留失败恢复 |
| 4 | 优化目录和下载等待 | 先显示上次已验签目录，再后台检查；能取消尚未开始的队列项；已验证下载才进入安装；不削弱签名和哈希检查 |
| 5 | 根据诊断决定是否复用插件进程 | 先量出启动开销；只有收益明确才改进程生命周期，并保留超时、崩溃隔离和跨版本清理 |

测试只围绕修改的路径：软件模拟超时、错序回复、失败恢复；需要写设备的新增功能才做实机往返。相同固件、相同协议且未修改的已通过路径不反复运行整套测试。优化记录分别列出“代码消除的等待”与“实际测量结果”，没有测量时不承诺提升比例。

设备接入另见[驱动库任务队列](https://github.com/chenran0408/peripheral-desk-drivers/blob/main/docs/ADAPTATION-ROADMAP.md)。主程序保持通用，不因新型号加入协议代码。

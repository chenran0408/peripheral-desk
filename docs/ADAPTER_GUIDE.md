# 设备适配框架

## 各层职责

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 设备目录 | `src/devices.rs` | 稳定 key、型号、严格 HID 匹配、图片、范围与选项 |
| 通用模型 | `src/model.rs` | 状态、设置命令、可序列化参数，不放句柄 |
| 协议适配 | `src/adapters/`、`src/keyboard.rs` | 打开通道、读写、型号校验和读回确认 |
| 编解码 | `src/protocol.rs` | 帧结构、校验、位域和字段编辑，可纯数据测试 |
| Windows 传输 | `src/hid.rs`、`src/keyboard.rs` | HID 枚举、Feature、带超时的 overlapped Input/Output |
| 刷新与存储 | `src/backend.rs` | 设备调度、缓存、断开状态、偏好和提醒 |
| 展示 | `src/ui.rs`、`src/paint.rs` | 首页、详情、元数据生成的高级设置、托盘 |

`DeviceSession` 是本次整理出的适配边界：

```rust
pub trait DeviceSession {
    fn read(&self) -> Result<State>;
    fn apply(&self, action: Action) -> Result<()>;
}
```

`read` 返回真实读数。`apply` 必须校验范围，保留无关字段，等待协议确认，再读回确认最终值。`Ok(())` 不应仅代表发送成功。

## 接入同协议设备

1. 在 `REGISTRY` 添加独立 `DeviceSpec`，使用长期稳定的 `key`，不要以数组位置作为配置身份。
2. 匹配 VID/PID、usage page、报告长度和产品名。共享接收器还要读型号签名，防止误操作其他型号。
3. 声明实际支持的 DPI 范围、回报率、休眠选项和高级设置；填入图片及来源。
4. 增补真实报告夹具；验证读数、离线、休眠、错误帧和设置读回。
5. 记录固件、连接方式和实测状态，更新功能表。

注册表中的顺序只影响展示。启动时按 key 恢复缓存；新增型号不会继承其他设备的电量。首页前三台使用大卡片；四台起每页显示四台，新增设备自动分页。托盘内容由注册表生成。

## 接入新协议

1. 给 `Adapter` 增加协议种类，在 `adapters/` 实现 `DeviceSession`，在 `adapters::open` 添加工厂分支。
2. 把纯编解码放进独立模块，传输复用 HID 层或增加明确的传输实现。
3. 同一语义复用 `Action`；新语义先在模型中定义，再在该设备的能力表声明。UI 不发送原始 HID 字节。
4. 高级枚举设置使用 `SettingSpec { key, title, hint, choices }`，统一页面会生成选项，并在没有新鲜读数时禁用。
5. 对完全不同的功能（改键、宏、逐键颜色）增加结构化模型与专用编辑器；不要把原始字节塞进通用数值选项。

设备协议为编译时注册，不加载任意协议脚本。G2 Pro 音效另有一个内容校验的 SDK 桥接入口，只在隔离进程加载指定版本组件。加入新适配器后重新编译发布。

## 状态与错误约定

- `present`：接口已枚举；`fresh`：本轮收到有效设备读数。两者不可混同。
- 休眠或断开后保留电量缓存，但清除可写设置与充电状态，UI 标明缓存含义。
- 电量与可选设置分别处理；某项设置读取失败，不应把有效电量丢弃。
- 使用 `error`、`settings_error` 返回可理解的错误。未知响应、校验失败或字段越界时禁止写入。
- Feature、Input/Output 的 Report ID、报告长度必须分别校验。不要把 `send` 成功当作设备接受。
- 超时后取消并排空 overlapped I/O，再释放缓冲区。

设置队列按“设备 + 设置字段”合并，仅覆盖同一字段的旧值，保留其他设置。HID 操作在后台单线程批次中执行，UI 保持响应；停止调整 1.5 秒后提交。

## 验证

先运行纯数据测试与 mock 刷新引擎测试，再做实机验证：只读 → 同值写入 → 修改值并恢复 → 退出重开后读回。不要在 CI 中访问硬件。

已有测试覆盖：旧缓存兼容、接收器/型号匹配、断开缓存、错误写入传播、队列合并、校验与错误帧、DPI 表无关字段保留、传感器独立字段、灯效颜色位保留。

## 后续扩展点

按键和宏还需按设备协议分别实现。建议结构化 `Binding`、`MacroStep` 和 `Profile`，统一编辑器和校验，具体序列化放入适配器；不能将某个品牌的数据布局视为通用格式。蓝牙、HyperPolling 接收器等也要单独声明和测试。

## 音频适配

`Kind::Headset` 没有电池、DPI、回报率或休眠选项。空能力表不能进入鼠标/键盘控件布局。首页与托盘显示 USB 供电，不生成未知电量或低电提醒。

`adapters/audio.rs` 通过 Core Audio 枚举端点并读写音量。按 G2 Pro 产品名区分 GAMING / CHAT / 麦克风，拒绝相同通道的歧义匹配。COM 句柄在所属线程释放；PROPVARIANT 与分配的字符串分别释放。

`audio_fx.rs` 将已验证参数声明为 `FxSpec { key, channel, property, max, offset }`。`channel` 显式区分三个端点，`offset` 仅用于无符号状态模型保存带符号 EQ 值（20 代表 0 dB），SDK 原始 EQ 单位为 1 dB。UI 分页由参数组映射，新增音效要同时补充能力元数据。

厂商 SDK 只在 `--audio-fx-worker` 子进程内调用：标准输入请求、标准输出结果、8 秒超时、崩溃隔离、绝对路径和已验证文件 SHA-256。SDK 确认 USB VID/PID/MI 与端点角色后才写入；每次修改先读取旧值，写入后核对，失败时尝试恢复。部分可选能力不存在时不返回虚构默认值，控件随能力禁用。Windows 禁用音频增强时不通过读操作擅自打开。

发布包禁止包含官方 SDK、驱动、安装程序或反编译输出。用户从自己的官方安装目录连接组件，本地路径只存入被 Git 忽略的 `data/hecate-sdk.json`。

运行 `python scripts/test_hecate_fx.py --apply --report <报告路径>` 可做音效参数往返测试；不加 `--apply` 只读取。测试前保存基线，每项更改后读回并恢复，最后比较完整参数表。不播放声音、不录音，也不据此宣称已经完成听感验证。

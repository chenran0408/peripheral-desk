# 迈从驱动中心原生化路线图

本轮分批实施记录及各阶段验收标准如下。评审基线为外设盒 `0.4.11-preview.19`（`08cdf90`）和驱动库 `af12753`。用户始终安装一个外设盒。型号及其协议由可独立更新的插件提供，同一项设置只有一个日常入口。

## 用户看到什么

「电量」继续显示读数及来源。「设备调节」首先展示用户已连接的可调设备，其次展示已安装的离线设备。品牌分类留在插件管理中。从电量、托盘或设备调节进入时，始终带上点选的那一台实物。已知型号可以先显示产品外观。各项编辑在读到这台设备的当前配置后开放，接收器在线和外设已唤醒分别显示。

保留 M HUB 的实物布局、点选、拖放、颜色预览和动效。已迁移的功能进入原生页面，其他现有功能在同一窗口打开本地网页的对应页面。个人网页工作区、样式、脚本和本地模板在迁移期间继续可用。账号与云服务不在范围内。

## 交付顺序

| 批次 | 实施安排 | 交付与验收 |
| --- | --- | --- |
| 1 · 保住写入，量出基线 | 让当前网页的 G75 写入队列向宿主报告未完成、成功和失败。先实现切页后的写入交接，完成后再释放设备会话。分别记录点击、首帧、目标设备可编辑、关键写入确认四个时刻。 | 用当前网页记录程序刚启动时首次进入、切回电量后再次进入两组基线。连续改两键后立即切页，两笔修改各有结果。中途断连时提示需要重读，已有读回依据时才显示已确认。此批可单独发布。 |
| 2 · 把操作交给点选的设备 | 主程序区分插件型号、物理设备、接收器接口。将目标传给新插件请求和网页桥，按实际冲突的接口管理读取、写入及占用。旧插件维持单设备路径；同时出现多只同型号且无法定向时不提供含糊的写入。按设备更新忙碌状态，避免后台轮询锁住整个界面。 | A5 常驻宏运行时仍可打开独立接收器上的 G75，另一台设备继续报电量。慢设备不挡「检查更新」。用两个同型号模拟实例验证选择第二只时请求确实发往第二只。 |
| 3 · G75 Pro 原生改键 | 先交付可视化键盘、普通/Fn/Fn2 三层切换、板载读回、点选及拖放改键。复用原生插件和原版外观图，按实际布局建立按键命中区域。后续小版在同一画布上加入逐键颜色、亮度和已适配灯效。 | 从电量页点 G75 即可显示键盘，已迁移页面不创建 WebView。改第二键基于已读回的当前层，保留前一键、未知映射与保留字节。切页后能看到最后一次写入结果。分别比较首帧和可编辑耗时。 |
| 4 · 初代 A5 Ultra 原生调节 | 复用目标选择、状态显示、写入确认、图片与热点绘制。先迁移已适配的 DPI、回报率、休眠和普通改键，再接防抖及抬升高度。具体范围、档位和动作按型号声明。 | 两只接收器同时存在时，点 A5 进入 A5。只有接收器在线时显示等待鼠标唤醒。只对这次改变的关键写入检查读回，保留既有协议验证。A5 初代已测样机的宏页长度为零，常驻软件宏继续单独标识。 |
| 5 · 按协议系列扩展 | 从现有 0x4D 插件中选一款已有独立板载操作的型号，检验通用组件能否服务后续贡献者。鼠标板载配置、宏编辑按型号开放。磁轴触发、校准和高级联动各自迁移。 | 每个型号按功能登记原生、内置网页、设备不提供或待接入。用户已有本地模板随对应功能提供导入或继续使用原入口。仅在功能、已有配置与用户常用交互都有去向后移除对应网页入口。 |

## 本轮交付范围

主程序 `0.4.12-preview.2` 与 G75 Pro、初代 A5 Ultra、K5 Ultra 三款 `0.4.13-preview.49` 插件共同提供本次升级。其他已装插件可沿用。普通用户从「设备调节」按实物进入；「偏好设置 → 写入记录」保留本次运行最近的设备写入结果。插件作者可参考[可点选设备图与分层读取](NATIVE-CONTROL-SURFACES.md)和[32 个迈从型号的功能对照](https://github.com/chenran0408/peripheral-desk-drivers/blob/main/docs/MCHOSE-EDITORS.md)。

- G75 普通层先单独读回，切到 Fn、Fn2 或逐键颜色时再读取对应部分。模拟实物已从 Win32 编辑器连续拖放两次后立即切页，两笔修改读回、其余层保持原值。原版网页的 G75 写入也会在离页后返回结果。
- 初代 A5 Ultra 保留现有性能设置和六个物理按键。两台同型号的定向写入、拔除后的隔离通过模拟接收器验证。常驻宏恢复与设备配置导入均使用打开时选定的设备。
- K5 Ultra 用自己的型号图片、键位热区和回复复用按键及宏编辑器。板载宏容量来自固件，型号验证依据为公开协议实现。磁轴、原厂模板、个人样式等随原有离线网页继续提供。厂商固件更新及依赖厂商桌面服务的联动仍见[兼容记录](MHUB-COMPATIBILITY.md)。

## 并行分工

- **主程序与编辑器**负责从点击开始保留设备身份、每台设备的写入队列、切页反馈，以及统一的页面入口。需要先渲染布局时可以使用型号素材，写入依据只来自当前设备。
- **驱动库与素材**负责协议、型号能力、报告范围、键位到协议槽的映射、型号图片及其来源。首批只抽取 G75 和 A5 用得上的共用部分。后续贡献者可用新的型号清单和样本复用已发布的编辑器。
- **发布与更新**可从第一批并行做。统一打包器与宿主对 ZIP 条目数的约束，让插件能声明其依赖的最低预览版或宿主能力。用准备发布的实际 ZIP 走客户端安装、更新及回退，核对配置保留，再发布依赖新编辑器的插件。此项不需要设备参与。

## 性能与维护

首帧衡量「用户多久能看到自己点的设备」，可编辑时间衡量「多久拿到真实板载值」。使用相同设备、连接方式和唤醒状态比较。首次展开新版离线资源单列，日常打开另计。只有进入仍由网页提供的功能或个人网页工作区时才启动 WebView。复用已验证的目录索引，把初始化和扫描的改善与硬件回复等待分别记录。

每次交付说明已迁移的型号和功能、仍走本地网页的功能、实际测得的冷/热时间、安装包和受影响插件的实际体积。保留插件签名、离线安装、上一版本回退和用户配置。更新厂商资源时登记版本、出处和使用条件，区分上游实物报告、本项目实测和样本检查。只对修改过的关键写入做定向验证。
